01

Goal & scope

Add Agent Strategy alongside Random Strategy. Generate one theoretical Bet per eligible game where possible, and measure performance through existing Runs, profit and ROI.

Build now

Generic agent engine, one Markdown profile, autonomous web research and saved Bet reasoning.

Later

Additional profiles and self-improvement, including profile versioning.

02

Agent profiles

Markdown · behavior

Identity, outlook, personality, strategy and research principles.

Python · execution

Model, tools, game context, output validation and persistence.

FootballAnalysisExpert.md Initial profile · illustrative

Role: Evidence-driven college football analyst. Evaluate covering the spread, not simply winning.

Outlook: Analytical, skeptical, balanced; prefer verified facts.

  • Verify quarterback availability and key absences.
  • Compare offense and defense against similar opponents.
  • Consider rest, travel, coaching and venue.
  • Check weather at kickoff.
  • Consider both sides; distinguish fact from opinion.
  • Choose a supplied selection and explain the key factors concisely.

The Markdown file is stateless, server-controlled and contains no credentials or application logic.

Local · inference

Python runs in the backend; Ollama runs locally on the Mac. Model and host are configurable; no inference API key or per-token fee.

External · research only

web_search is our provider-independent tool. Initially use keyless DuckDuckGo search through the community ddgs library, explicitly selecting its DuckDuckGo backend. No Ollama search service or search API key is required.

DuckDuckGo access can be throttled, blocked or return no usable results. Keep search bounded and report failed research through the existing retry/skip policy; do not silently switch search providers. Return search snippets and links; full-page crawling is outside this first version.

One analysis may include multiple calls. Bound timeouts, tool calls and concurrency; start sequentially. Treat search results as evidence, not instructions.

Application owns the quote and stake. Resolve the returned selection ID to the original saved line, price and provenance. Never trust model-generated odds or accounting.

04

Run lifecycle

Generate predictions only when creating a Run. Use the same strategy registry for Random and Agent.

A · Read

Capture inputs

  • Check creation-key replay
  • Resolve eligible games and quotes
  • Check bankroll
B · No DB locks

Predict each game

  • Dispatch predict()
  • Research and validate output
  • Retry failed predictions once
C · Short write transaction

Revalidate & save

  • Recheck replay, eligibility, quotes and bankroll
  • Save successful Bets and skipped games
  • Commit immutable snapshots

Failure handling · retry, then best effort

ScenarioFinal skip reason
Model unavailable / timeoutagent_unavailable
Research fails / tool budget exhaustedresearch_failed
Invalid selection or reasoninginvalid_agent_decision
Saved quote changedquote_changed

Retry with fresh eligible inputs if the quote has changed before the final write; if it changes again at commit, skip it. Existing eligibility skips still apply. Never research under DB locks or fall back to Random.

Example: 50 eligible games → 47 successful predictions after retry → 47 Bets and 3 reported skips. Replaying an already-created Run returns the saved outcome without new inference.

Keep existing Run ownership, settlement and profit/ROI calculations. Shared Strategies remain universal.

06

Local setup · Ollama

1

Install on macOS. Download Ollama, move it to Applications and launch it. Run natively for Apple GPU acceleration.

2

Download and test the model.

ollama run gpt-oss:20b
3

Add the native SDK and search library, then connect from Docker. Install these Python dependencies in the backend environment during implementation:

uv add ollama ddgs # Backend runtime settings OLLAMA_HOST=http://host.docker.internal:11434 OLLAMA_MODEL=gpt-oss:20b

Test the host endpoint from the backend container. If unreachable, configure Ollama's bind address for Docker access only; do not expose its unauthenticated API publicly. Use ollama.AsyncClient(host=...) for local chat; no API key required.

4

Use DuckDuckGo for research. Expose our Python web_search(query) tool using DDGS().text(query, backend="duckduckgo", max_results=5). Normalize results to title, URL and snippet. No account or search key setup; verify connectivity from the backend container. Keep the tool interface independent of the provider so a future provider change does not alter the agent profile.

References: macOS setup · Python SDK · Tool calling · DDGS search library · Docker networking. DuckDuckGo search replaces the previous hosted Ollama search choice as requested by CHIP on November 19, 2026.
